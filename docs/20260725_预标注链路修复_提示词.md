# yolo-studio 预标注链路修复（实现提示词）

> 自包含任务书。项目位于 `~/project/yolo-studio/`。
> 三个问题都是在真实使用「头盔识别」场景时暴露的，**均已复现并定位到具体代码行**（2026-07-25）。
> 行号基于当前 HEAD，改动后会漂移，请按代码内容定位。

## 零、背景：一次真实事故

用户新建了头盔识别数据集（类别 `[helmet, no_helmet]`），手工标了 107 张，训出第一版模型，然后点「模型预标注」，接连踩了三个坑：

1. **静默数据污染**：预标注用的不是新训的头盔模型，而是 `weights/0517_yolo26s_wheelie_multi-rider.pt`（翘车头/多人骑车模型）。它输出的 `wheelie`(0)/`multi rider`(1) 被**原样按索引**映射成 `helmet`(0)/`no_helmet`(1)，**77 张图被打上 83 个完全错误的标注**，界面上毫无提示。
2. **OpenVINO 崩溃**：换成正确模型后，预标注直接失败：
   ```
   Can't set the input tensor with index: 0, because the model input
   (shape=[1,3,416,416]) and the tensor (shape=(8,3,640,640)) are incompatible
   ```
3. **失败即终止**：`.pt` 明明能正常推理，但 OpenVINO 一报错整个任务就 failed，没有降级。

三个问题都在预标注链路上，一起修。

## 一、P0-1 ★ 预标注类别静默错配（会污染数据，最严重）

### 根因

`app/services/autolabel_svc.py:93`：

```python
if 0 <= pred_index < len(dataset_classes) and not class_mapping:
    return pred_index          # ← 没传 class_map 时，直接拿模型的类别索引当数据集索引用
```

模型认识 `[wheelie, multi rider]`，数据集是 `[helmet, no_helmet]`，语义毫无关系，代码却因为"索引都在范围内"就直接映射了。

**训练那边是有校验的**（`train_svc.check_finetune_compat` 会拦住类别不兼容的底模），预标注这边漏了。

### 为什么会用错模型

`app/services/model_svc.py:63` 的 `get_default_autolabel_path()`：数据库里没有 `is_default_autolabel=1` 的模型时，会**回退到 `weights/` 下的 0517 权重**。

用户训完模型后没有点「发布到模型仓库」，仓库是空的，于是静默走了这个兜底。

### 改法

**① 加类别兼容校验**（`autolabel_svc.py`，推理开始前）

拿模型的 `model.names` 和数据集的 `classes` 比对：

```python
def check_autolabel_compat(model_names: dict, dataset_classes: list[str],
                           class_map: dict) -> None:
    """模型类别与数据集类别不匹配时，直接拒绝，不允许静默按索引硬套。"""
    if class_map:
        return                      # 用户显式指定了映射，尊重用户
    model_labels = [str(v) for v in model_names.values()]
    norm = lambda s: re.sub(r"[^a-z0-9]+", "", str(s).lower())
    ds_norm = {norm(c) for c in dataset_classes}
    hit = sum(1 for m in model_labels if norm(m) in ds_norm)
    if hit == 0:
        raise ValueError(
            f"这个模型认识的是 {model_labels}，和数据集的 {dataset_classes} 对不上，"
            f"不能用来预标注。请改用在本数据集上训练的模型，"
            f"或在高级参数里手工指定类别映射（class_map）。"
        )
```

- **一个都对不上 → 直接报错拒绝**（当前事故就是这种情况）
- 部分匹配 → 允许执行，但把未匹配的类别记进任务 message 提醒用户
- 用户显式传了 `class_map` → 尊重用户，不拦

**② 兜底逻辑不要再抓不相干的模型**（`model_svc.py:63`）

删掉回退到 `weights/0517_*.pt` 的分支。没有默认预标注模型时，就明确返回 `None`，让上层报人话错误：

> "还没有设置默认预标注模型。请先到「训练」页把训练结果发布到模型仓库，再到「模型仓库」点「设为默认预标注模型」。"

**理由**：0517 是给飙车炸街场景准备的，对任何新场景的数据集来说都是错误的默认值。冷启动时用户宁可看到一句清楚的提示，也不要拿到一批悄悄写错的标注——**错误标注比没有标注危害大得多**，它会被当成正确数据训进模型。

**③ 前端提示**

预标注面板的模型下拉框里，把**在本数据集上训练过的模型排在最前面**并标注"（本数据集训练）"，其它模型标注它认识的类别，例如 `0517_yolo26s（翘车头/多人骑车）`。让用户选之前就能看出来对不对。

### 验收

1. 用 `weights/0517_yolo26s_wheelie_multi-rider.pt` 对 `[helmet, no_helmet]` 数据集发起预标注 → **必须报错拒绝**，错误信息里同时列出两边的类别
2. 用本数据集训练的模型预标注 → 正常执行
3. 手工传 `class_map={"wheelie": 0}` → 允许执行（尊重用户显式指定）
4. 模型仓库为空时发起预标注 → 报"还没有设置默认预标注模型…"，**不再静默使用 0517**

## 二、P0-2 ★ OpenVINO 输入形状不兼容导致任务失败

### 根因

导出与推理的参数对不上，而 OpenVINO 导出的是**静态形状**：

| | 导出时（写死在模型里） | 预标注推理时 |
|---|---|---|
| 尺寸 | **416×416**（跟训练的 imgsz） | 640（`app/schemas.py:42` 的默认值） |
| batch | **1** | 8（`app/config.py:53` 的 `INFER_BATCH_SIZE`） |

实测确认模型输入形状：

```
输入名: x.1 | 形状: [1,3,416,416]
```

`app/infer/engine.py:155` 的导出没有开动态形状：

```python
out = model.export(format="openvino", imgsz=imgsz, half=False, device="cpu")
```

### 改法（三条都要做）

**① 导出时开启动态形状**（治本）

```python
out = model.export(format="openvino", imgsz=imgsz, half=False,
                   device="cpu", dynamic=True)
```

这样模型能接受任意尺寸和 batch。代价是推理速度略降（个位数百分点），换掉一整类问题，值得。

**② 把导出参数记进数据库**（兜底对齐）

`model` 表用 `_ensure_columns` 幂等迁移加两列（照抄 `app/db.py:143` 里加 `ov_status` 的写法）：

```python
_ensure_columns(conn, "model", {
    "openvino_path": "TEXT", "ov_status": "TEXT",
    "export_imgsz": "INTEGER",     # 导出时用的尺寸
    "export_dynamic": "INTEGER",   # 是否动态形状：1/0
})
```

预标注加载 OpenVINO 版本时：

- 若 `export_dynamic != 1`，**强制**把推理 `imgsz` 改成 `export_imgsz`、batch 改成 1
- 并在任务 message 里说明："已按模型要求把尺寸调整为 416、batch 调整为 1"
- 不要静默改，用户需要知道为什么速度和预期不一样

**③ 形状不兼容时自动降级到 .pt**（关键）

现在的逻辑是"OpenVINO 状态 ready 就用它"，但没考虑"用起来才发现不兼容"。推理调用要包一层：

```python
try:
    results = ov_model.predict(...)
except Exception as exc:
    logger.warning("OpenVINO 推理失败，降级用 .pt：%s", exc)
    task_mod.update_task(task_id, message="OpenVINO 不兼容，已自动改用 .pt 继续")
    results = pt_model.predict(...)
```

`.pt` 明明能跑，不该让整个任务失败。降级要**记进任务 message**，让用户知道这次没走加速路径。

### 验收

1. 用训练产出的模型（imgsz=416）发起预标注，**imgsz 保持默认 640** → 任务正常完成，message 里说明已自动对齐尺寸
2. 新发布的模型，`export_dynamic=1`，用 640 和 416 两种尺寸预标注都能跑
3. 人为破坏 OpenVINO 目录（改坏 .xml）→ 任务**仍然成功**，走 `.pt` 降级，message 有提示
4. `INFER_BATCH_SIZE=8` 时不再报 shape 不兼容

## 三、P1 清理与体验

### 3.1 清理测试垃圾模型

`data/models/` 里有两个冒烟测试留下的 `smoke_1784972096-059a2f`、`smoke_1784971592-513d50`，混在模型仓库里干扰选择。

- 让 `scripts/smoke_test.py` 在结束时**清理自己创建的数据集和模型**（加 `--keep` 参数保留用于调试）
- 模型仓库页的删除功能要**连带删除** `data/models/<id>.pt` 和 `<id>_openvino_model/` 目录，别只删数据库记录留下孤儿文件

### 3.2 预标注默认阈值

当前 `AutolabelRequest.conf` 默认 0.25。实测第一版模型（训练样本少）在 0.25 下 40 张图有 35 张检不出任何东西，预标注等于没用。

- 预标注面板把 conf 滑块**默认值降到 0.15**，并在旁边标注："阈值越低框越多但越不准；新训练的模型样本不足时建议 0.1~0.2"
- 这只是默认值调整，用户仍可自由调节

### 3.3 提供"清空预标注"入口

事故发生后，用户只能手写 SQL 才能清掉错误的 auto 标注。数据集页加一个操作：

```
POST /api/datasets/{id}/annotations/clear-auto
```

- 只删 `source='auto'` 的标注，**绝不碰 `source='manual'` 的人工标注**
- 把对应图片的 `review_status` 从 `auto` 改回 `unlabeled`，`box_count` 归零
- 前端二次确认，提示"将删除 N 个模型自动标注的框，你手工标的不受影响"
