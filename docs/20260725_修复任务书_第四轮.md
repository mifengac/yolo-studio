## 一、P0-1 ★ 训练命令不可执行（训练功能完全不可用）

### 现象

```
命令: python -m ultralytics detect train model=.../yolo26n.pt epochs=2 imgsz=320 ...
/path/.venv/bin/python: No module named ultralytics.__main__;
    'ultralytics' is a package and cannot be directly executed
训练失败 exit=1
```

任务状态直接 `failed`，`last_epoch=0`，没有任何产物。

### 根因

`python -m ultralytics` 这个调用方式**在 ultralytics 8.4.105 里不存在**——该包没有 `__main__.py`，无法被 `-m` 直接执行。

这个写法出自第一轮任务书（为替换掉原来只找 Windows `yolo.exe` 的 `_resolve_yolo_executable()`），属于**任务书本身给错了**，实现方照搬所致。

### 位置

`app/services/train_svc.py`，构造训练命令处（搜索 `"-m", "ultralytics"` 或 `detect`、`train` 的 subprocess 组装）。
**注意：断点续训（`resume_job` / `_handler_resume`）走的是同一套命令构造逻辑，务必一并检查，不要只改一处。**

### 修法（已实测跑通）

ultralytics 装包时会生成 `yolo` 可执行文件，且**与 python 解释器同目录**——本地是 `.venv/bin/yolo`，容器里是 `/usr/local/bin/yolo`，两边都成立：

```python
import shutil, sys
from pathlib import Path

def _resolve_yolo_bin() -> str:
    """定位 ultralytics 的 yolo 可执行文件（跨本地 venv 与容器）。"""
    cand = Path(sys.executable).parent / "yolo"
    if cand.is_file():
        return str(cand)
    found = shutil.which("yolo")
    if found:
        return found
    raise FileNotFoundError(
        "未找到 ultralytics 的 yolo 命令，请确认 ultralytics 已正确安装"
    )
```

命令组装改为：

```python
cmd = [
    _resolve_yolo_bin(), "detect", "train",
    f"data={yaml_path}", f"model={base_path}",
    f"epochs={epochs}", f"imgsz={imgsz}", f"batch={batch}",
    "device=cpu", "amp=False",
    f"workers={workers}", f"freeze={freeze}", f"cache={cache}",
    f"patience={patience}",
    f"project={runs_dir}", f"name={job_id}", "exist_ok=True", "verbose=True",
]
```

**实测验证记录**（用上述方式在本机跑通）：

```
2 epochs completed
Optimizer stripped from .../weights/last.pt, 5.3MB
Optimizer stripped from .../weights/best.pt, 5.3MB
Validating .../weights/best.pt...
   Class Images Instances Box(P R mAP50 mAP50-95)   ← 训练后自动 val 正常
```

如果不想依赖 console script，退路是内联脚本（二选一即可，不必都做）：
```python
cmd = [sys.executable, "-c",
       "from ultralytics import YOLO;"
       f"YOLO(r'{base_path}').train(data=r'{yaml_path}', epochs={epochs}, ...)"]
```

### 验收

1. `python scripts/smoke_test.py --train` 本地跑通，任务 `status=success` 且 `best_pt` 有值
2. **容器内**也跑一次 `--train`（路径推导在容器里同样成立，但必须实测）
3. 训练跑到一半点「取消」，进程能被正确终止
4. 训练中断后点「继续训练」，`resume` 路径同样能跑起来（**这条最容易漏**）

## 二、P0-2 ★ Dockerfile 构建失败（镜像根本出不来）

### 现象

```
#16 ModuleNotFoundError: No module named 'cv2'
ERROR: failed to build: process "/bin/sh -c mkdir -p /root/.config/Ultralytics ..." exit code: 1
BUILD EXIT: 1
```

### 根因

Dockerfile 里这句：

```dockerfile
&& (pip uninstall -y opencv-python || true)
```

`opencv-python` 和 `opencv-python-headless` **共用同一个 `site-packages/cv2` 目录**。卸载 `opencv-python` 会把 `cv2` 目录整个删掉，于是 headless 虽然还在 pip 记录里，但**实际文件已经没了** → 后续 `from ultralytics.utils import SETTINGS` 直接 `ModuleNotFoundError: No module named 'cv2'`，构建中断。

`|| true` 兜住的是"uninstall 命令本身失败"，兜不住"uninstall 成功但把 cv2 弄坏了"。

这条优化建议出自第三轮任务书，任务书里虽然写了"如果卸载后报错就还原这条改动"，但没说清失败会发生在构建阶段。

### 修法（两个方案都已实测，二选一）

**方案 A（推荐，最保险）**：直接删掉那句卸载，接受多占约 116 MB。

```dockerfile
RUN pip install --upgrade pip \
    && pip install torch==2.13.0 torchvision==0.28.0 --index-url https://download.pytorch.org/whl/cpu \
    && pip install -r /app/requirements.txt \
    && pip install "git+https://github.com/ultralytics/CLIP.git"
```

**方案 B（省 116 MB，已验证可行）**：卸载后**强制重装 headless 把 cv2 装回来**，顺序不能颠倒。

```dockerfile
    && pip install "git+https://github.com/ultralytics/CLIP.git" \
    && pip uninstall -y opencv-python \
    && pip install --force-reinstall --no-deps opencv-python-headless==5.0.0.93 \
    && python -c "import cv2; from ultralytics import YOLO; print('cv2 OK', cv2.__version__)"
```

实测验证记录（在现有镜像内演练）：
```
--- 卸载后 ---        ModuleNotFoundError: No module named 'cv2'      ← 复现了构建失败
--- 强制重装后 ---     cv2 OK 5.0.0
                      ultralytics OK
```

**方案 B 末尾那句 `python -c "import cv2; ..."` 是必须的**——把校验放进构建步骤，以后再出类似问题会在 build 阶段就炸掉，而不是等到内网部署才发现。

### 验收

1. `docker build -t yolo-studio:latest .` **成功**（这是本条的核心，当前是失败的）
2. 容器内 `python -c "import cv2, ultralytics; print(cv2.__version__)"` 正常
3. 记录**新的镜像体积**（加了 CLIP 权重 338 MB + CLIP 包，几乎肯定超过 3 GB），并把 `README.md` 里的体积预期与实测值一起订正——现在 README 写的"实测约 2.9 GB"是加 CLIP 之前的旧数据

## 三、P1-1 冒烟测试把训练改成默认执行

### 理由

训练是本项目最核心的功能，却因为挂在 `--train` 可选开关后面，**连续三轮都没被任何一次冒烟覆盖到**，导致一个致命 bug 潜伏至今。核心路径不该靠可选开关保护。

### 修法

`scripts/smoke_test.py`：把短训改为**默认执行**（`imgsz=320`、`epochs=2`、`batch=4`，本机实测几十秒即可跑完），另外提供 `--no-train` 用于确实想跳过的场景。

同时确认：训练失败时脚本必须以**非零退出码**结束并打印 `run_dir/train.log` 的最后 20 行，方便一眼看到原因（当前是靠 `assert` 抛 traceback，日志内容没打出来，排查得自己去翻文件）。

### 验收

`python scripts/smoke_test.py` 不加任何参数，能完整跑完「建集 → 导图 → 预标注 → 存标注 → 预估 → 训练 2 epoch → 校验 best.pt」，最后输出 `SMOKE OK`。
