## 零、问题

智能切图导入时，**同一个人经常被切成好几张图**，肉眼看是"一张稍大、一张稍小"，内容几乎一样。

### 根因

第一级 `yolo26n` 检测 person 时，同一个人身上会保留多个高度重叠的框。ultralytics 默认 NMS 阈值 `iou=0.7` 偏宽松——两个框重叠没超过 70% 就都算"不同目标"。而 `crop_svc.py` 拿到框之后**逐个切图，没有做任何去重**，于是重复框变成了重复切图。

### 实测证据

对 12 张真实卡口图跑 person 检测（`conf=0.25, imgsz=1280`）：

```
0652_已戴头盔  两框 IoU=0.94   338x503  vs  336x481   ← 几乎完全重合
0577_未戴头盔  两框 IoU=0.98   275x292  vs  273x293   ← 只差 2 像素
0121_未戴头盔  两框 IoU=0.90    51x192  vs   56x193
0696_已戴头盔  两框 IoU=0.73   276x471  vs  354x502

12 张图共 88 个 person 框，高度重叠(IoU>0.5)的有 6 对
→ 约 7% 的切图是重复的
```

### 危害（双重损失，比看起来严重）

1. **标注工时浪费**：用户手工标了 715 张切图，其中约 50 张是同一个人标了两遍
2. **训练分布被扭曲**：同一目标在数据集里出现两次，等于给这类样本**偷偷加了权重**，模型会过度关注它们

## 一、P0 切图前对 person 框去重

### 位置

`app/services/crop_svc.py`，第一级检测拿到 person 框之后、进入切图循环之前。

### 改法（两条都做）

**① 收紧检测阶段的 NMS 阈值**

检测调用加上 `iou` 参数：

```python
results = model.predict(
    source=...,
    conf=p["conf"],
    iou=p["det_iou"],        # ← 新增，默认 0.45（ultralytics 默认 0.7 太松）
    imgsz=p["imgsz"],
    device="cpu",
    verbose=False,
)
```

`_DEFAULT_PARAMS` 增加：

```python
"det_iou": 0.45,   # 检测 NMS 阈值，越小越不容易把同一个人拆成多个框
```

**② 切图前再做一次几何去重（兜底）**

只调 NMS 挡不住所有情况（比如一大一小的包含关系，IoU 可能算下来不高但明显是同一人）。所以在切图前再过一道：

```python
def _box_iou(a, b) -> float:
    ix1, iy1 = max(a[0], b[0]), max(a[1], b[1])
    ix2, iy2 = min(a[2], b[2]), min(a[3], b[3])
    if ix2 <= ix1 or iy2 <= iy1:
        return 0.0
    inter = (ix2 - ix1) * (iy2 - iy1)
    ua = (a[2]-a[0])*(a[3]-a[1]) + (b[2]-b[0])*(b[3]-b[1]) - inter
    return inter / max(ua, 1e-6)


def _contain_ratio(small, big) -> float:
    """small 被 big 覆盖的比例——处理"一个框套在另一个里面"的情况"""
    ix1, iy1 = max(small[0], big[0]), max(small[1], big[1])
    ix2, iy2 = min(small[2], big[2]), min(small[3], big[3])
    if ix2 <= ix1 or iy2 <= iy1:
        return 0.0
    inter = (ix2 - ix1) * (iy2 - iy1)
    return inter / max((small[2]-small[0]) * (small[3]-small[1]), 1e-6)


def dedup_person_boxes(boxes, iou_thr=0.5, contain_thr=0.8):
    """同一个人的多个重叠框只保留最大的那个。

    boxes: [[x1,y1,x2,y2], ...]
    返回去重后的框列表。
    """
    area = lambda b: (b[2]-b[0]) * (b[3]-b[1])
    ordered = sorted(boxes, key=area, reverse=True)   # 大框优先保留
    kept = []
    for b in ordered:
        dup = False
        for k in kept:
            if _box_iou(b, k) > iou_thr or _contain_ratio(b, k) > contain_thr:
                dup = True
                break
        if not dup:
            kept.append(b)
    return kept
```

在切图循环前调用：

```python
person_boxes = [b for b in detections if 类别匹配 and 框高 >= min_box_h]
before = len(person_boxes)
person_boxes = dedup_person_boxes(
    person_boxes,
    iou_thr=p["dedup_iou"],
    contain_thr=p["dedup_contain"],
)
skipped_dup_box += before - len(person_boxes)
```

`_DEFAULT_PARAMS` 再加两项：

```python
"dedup_iou": 0.50,       # 两框 IoU 超过此值判为同一个人
"dedup_contain": 0.80,   # 小框被大框覆盖超过此比例判为同一个人
```

**为什么保留大框而不是小框**：切图要包含车身（`bottom_ratio=1.3` 的设计目的），大框切出来的上下文更完整。

### 统计要闭合

完成消息里加上这一项，并保证各项相加等于检出总数：

```
处理大图 230 张，检出目标 892 个，
跳过重叠重复 61 个，跳过过小 143 个，跳过过暗 8 个，
跳过比例异常 3 个，跳过内容重复 12 个，切图入库 665 张
```

注意区分两种"重复"，别混为一谈：

| 名称 | 含义 |
|---|---|
| **跳过重叠重复** | 本次新增——同一个人的多个框（检测阶段产生） |
| 跳过内容重复 | 已有——不同原图切出了像素相同的图（sha1 去重） |

### 预览也要同步

`crop-import/preview` 必须应用同样的去重逻辑，保证**预览所见即入库所得**。

## 二、验收标准

| 项 | 标准 |
|---|---|
| 去重生效 | 用真实卡口图跑切图，完成消息里「跳过重叠重复」**大于 0** |
| 效果核对 | 同一批原图，去重前后切图数量下降约 **5%~10%**（实测重复率约 7%） |
| 不误删 | **抽查 20 组被去重的框**，确认是同一个人，没有把挨得近的两个人合并掉 |
| 大框优先 | 保留下来的是面积更大的那个框（切图能看到更完整的车身） |
| 预览一致 | 预览结果与全量入库的切图数量、内容一致 |
| 统计闭合 | 检出 = 重叠重复 + 过小 + 过暗 + 比例异常 + 内容重复 + 入库 |
| 回归 | 现有切图导入、预标注、训练全流程正常 |

**"不误删"这条最关键**：真实路口上两个人可能挨得很近（比如一车载两人），阈值定太松会把他们合并成一个，导致漏标。`iou_thr=0.5` 是保守值，验收时务必人工抽查。

### 建议的验证方式

```bash
# 同一批原图，改动前后各跑一次，对比切图数量
# 然后把被去重掉的框可视化出来（在原图上画出保留框和被删框），人眼确认
```
