# yolo-studio 训练样本筛选语义修正 + 切图统计补全（实现提示词）

> 自包含任务书。项目位于 `~/project/yolo-studio/`。
> 两个问题都是真实使用中暴露的，已定位到具体代码行（2026-07-26）。

## 零、背景

用户手工标注了 785 张图，勾选训练页的「仅已确认样本」后，系统显示**只有 2 张可用**，训练无法进行。

排查发现：785 张的状态是 `reviewed`，而筛选逻辑只认 `confirmed`。用户被迫手工执行 SQL 把状态批量改掉才能训练——这显然不对。

---

## 一、P0 ★ `only_confirmed` 筛选条件过严，把人工标注挡在门外

### 现状

`app/services/export_svc.py:43`：

```python
if only_confirmed and it.get("review_status") != "confirmed":
    continue        # ← 只认 confirmed
```

而标注器写入状态的规则是：

| 用户操作 | 写入状态 | 实际含义 |
|---|---|---|
| 画完框按 `A`/`D` 翻页（自动保存） | `reviewed` | **人工画的/改的** |
| 画完框按 `Enter` | `confirmed` | 人工画的/改的 |
| 模型预标注，无人审核 | `auto` | **机器标的** |

`reviewed` 和 `confirmed` 都是**人工把关过**的，区别仅仅是用户按了哪个键。真正需要区分的是「**人有没有看过**」——也就是要排除 `auto`。

现在的实现把 785 张人工标注当成不存在，只因为用户习惯用 `D` 翻页而不是 `Enter`。

### 这个缺陷造成的实际损失

用户为了能训练，只好在 `only_confirmed=False` 下训练，于是**未审核的模型预标注（`auto`）也进了训练集**。连续几版训练下来未审核占比从 47% 涨到 61%，模型出现明显退化：

```
干净验证集对比（同一验证集、同一 best.pt val 口径）
              训练集 847 张    训练集 2028 张
Recall           0.915     →     0.821
mAP50-95         0.728     →     0.672
helmet 召回      0.896     →     0.722
```

**训练数据翻了一倍多，模型反而更差**——这是伪标签自我强化的典型后果。而根源之一，就是用户没法方便地只用人工数据训练。

### 改法

**① 修正筛选语义**（`export_svc.py:43`）：

```python
# 人工把关过的状态：reviewed（改过/画过）与 confirmed（明确确认）都算
HUMAN_VERIFIED = ("reviewed", "confirmed")

if only_confirmed and it.get("review_status") not in HUMAN_VERIFIED:
    continue
```

建议把 `HUMAN_VERIFIED` 提成模块级常量，`export_svc.py` 内其它用到状态判断的地方统一引用。

**② 改前端文案**（`web/index.html:220`）：

```html
<label>
  <input type="checkbox" v-model="trainForm.only_confirmed" @change="refreshEstimate" />
  仅人工确认的样本（排除未审核的预标注）
</label>
```

现在的「仅已确认样本」说不清到底在排除什么，用户没法判断该不该勾。

**③ 改错误提示**（`export_svc.py:106`）：

```python
+ ("请先人工标注或审核一些图片（模型自动预标注的需要先审核）。" if only_confirmed
   else "请先标注一些图片。")
```

**④ 前端预估信息里给出构成**

调 `/api/train/estimate` 时，除了图片总数，再返回一行构成说明，让用户勾选前就知道会用到什么：

```
可用于训练 787 张（人工标注 785 + 已确认 2），已排除未审核预标注 1241 张
```

这样用户能直观看到勾与不勾的差别，不用去猜。

### 不要做的事

**不要**新增"严格模式（只用 confirmed）"这类选项。`reviewed` 和 `confirmed` 在本产品里没有实质区别（都是人工过目），再加一层开关只会让用户更困惑。保持一个清晰的二分：**人工把关过 vs 机器标的没人看过**。

### 兼容性

- 用户可能已手工把部分 `reviewed` 升级成了 `confirmed`，改动后行为一致，无影响
- 历史训练任务记录里的 `only_confirmed` 参数不用迁移，只影响新发起的训练
- 默认值保持 `True`（`schemas.py:98,111`）不变

### 验收

1. 数据集有 785 张 `reviewed` + 2 张 `confirmed` + 1241 张 `auto` 时，勾选「仅人工确认的样本」→ 可用样本数应为 **787**，不是 2
2. 不勾选 → 2028 张（含 auto）
3. 导出的训练集里**不含任何 `auto` 状态的图**（勾选时）
4. 数据集里只有 `auto` 没有人工标注时，勾选后报人话错误，提示先审核

## 二、P1 切图完成消息漏报"跳过重复"，数字对不上

### 现状

`app/services/crop_svc.py:401` 的完成消息：

```
处理大图 10 张，检出目标 61 个，跳过过小 0 个，跳过过暗 1 个，
跳过比例异常 0 个，切图入库 49 张，其中 0 张大图未检出任何目标
```

`61 - 0 - 1 - 0 = 60`，但入库只有 **49**，差的 11 张没有交代。

原因：`dataset_svc.import_files()` 内部会按 sha1 去重，返回值里有 `skipped_dup` 字段，但 `crop_svc.py:388` 只累加了 `imported`：

```python
imported_total += int(r.get("imported") or 0)
# skipped_dup 被丢弃了
```

去重行为本身是正确的（同一张切图重复导入没有意义），但**统计不闭合会让用户以为丢图了**。

### 改法

累加 `skipped_dup`（以及 `skipped_bad`，如果有），并写进完成消息：

```python
skipped_dup_total += int(r.get("skipped_dup") or 0)
skipped_bad_total += int(r.get("skipped_bad") or 0)
```

消息改成：

```
处理大图 10 张，检出目标 61 个，跳过过小 0 个，跳过过暗 1 个，
跳过比例异常 0 个，跳过重复 11 个，切图入库 49 张，其中 0 张大图未检出任何目标
```

要求：**各项相加必须等于检出总数**，即
`检出 = 过小 + 过暗 + 比例异常 + 重复 + 损坏 + 入库`。
实现完请用真实数据核对一次这个等式。

### 验收

1. 对同一个数据集连续跑两次切图导入，第二次的完成消息里"跳过重复"应等于第一次入库的数量，且各项数字相加闭合
2. 首次导入（无重复）时"跳过重复 0 个"
