  二、关于"不用手打标签"——有 7 条路，按性价比排序

  1. 用你现有的模型预标注（最该先做，立刻见效）

  你已经有 0517_yolo26s_wheelie_multi-rider.pt。新图先让它跑一遍，直接生成框，人
  只做"改一改、删一删、点确认"。实测能省 70%~80%
  的时间。你根本不存在冷启动问题。

  2. 迭代闭环（整个系统的灵魂）

  标 200 张 → 训一版新模型 → 用新模型预标下一批 500 张
     → 预标越来越准 → 人越来越只需点"确认" → 再训 → ...
  到后面基本就是"翻页 +
  按确认键"。这个闭环要做进系统里：训练产物能一键设为"默认预标注模型"。

  3. 开放词表零样本检测（新类别冷启动用）

  YOLO-World / YOLOE：直接输入英文描述，比如 motorcycle with front wheel 
  lifted、three people on one motorcycle，不用训练就出框。你 multi-rider
  里已经有权重了。适合以后加新类别（比如"不戴头盔""改装排气"）时，第一批图连人工
  都不用起头。

  4. 视频跟踪传播（如果你有视频源，收益最大）

  飙车炸街大概率有卡口视频。做法：视频抽帧 → 只标第 1 帧 → 用 ByteTrack/BoT-SORT
  把框自动传播到后面几百帧。一段 10 秒视频（250 帧）人工只标 1~2
  帧。这是数量级的差别。

  5. SAM 点击辅助（手工兜底时用）

  MobileSAM / SAM2：在物体上点一下，自动吐出精准框，不用拖拽拉框。对付预标注漏检
  的图，比手拉快 3 倍。模型文件几十 MB，离线可用。

  6. 主动学习排序（少标一半）

  模型对哪些图"最没把握"（置信度在 0.3~0.6 之间、或同一物体两个类别打架），就把
  这些图排到最前面让人标。模型已经很确定的图就别浪费人力了。同样标 500
  张，效果能顶 1000 张。

  7. 近重复图去重（别标废图）

  连拍/视频抽帧会有大量几乎一样的图，标 100 张相似图不如标 10
  张不同的。用感知哈希（pHash）或 CLIP
  向量聚类，自动把近重复图折叠成一组，只标代表帧。

  ▎ ⚠️ 离线约束：以上所有模型权重（YOLO-World、MobileSAM、CLIP）必须在外网机器上
  ▎ 提前下好塞进 weights/ 目录，并且要关掉 ultralytics 的自动联网下载（它会偷偷
  ▎ 下字体和权重，内网会卡住报错）。这一点我写进提示词里了。

● 纯 CPU 是个硬约束，会显著改变训练部分的设计。我先给你交个实底，再改设计。

  先说实话：E5-2697 v3 训练 YOLO 有多慢

  这颗是 2014 年的 14 核 28 线程 Haswell，多核还行但单核弱，没有 GPU
  就只能靠核数堆。我按你的机器估算（假设 1000 张训练图）：

  ┌─────────────────────────────────┬────────────┬─────────────────┐
  │              配置               │  单 epoch  │   跑 50 epoch   │
  ├─────────────────────────────────┼────────────┼─────────────────┤
  │ yolo26s + 640px（你现在的配置） │ 20~35 分钟 │ 17~29 小时 ❌   │
  ├─────────────────────────────────┼────────────┼─────────────────┤
  │ yolo26n + 640px                 │ 8~15 分钟  │ 7~12 小时 ⚠️    │
  ├─────────────────────────────────┼────────────┼─────────────────┤
  │ yolo26n + 416px                 │ 4~7 分钟   │ 3.5~6 小时 ✅   │
  ├─────────────────────────────────┼────────────┼─────────────────┤
  │ yolo26n + 416px + 冻结主干      │ 2~4 分钟   │ 2~3.5 小时 ✅✅ │
  └─────────────────────────────────┴────────────┴─────────────────┘

  三个能救命的招（我会写进设计）：

  1. 不要从 COCO 预训练从头开始，从你已有的模型接着训。你手里的
  0517_yolo26s_wheelie_multi-rider.pt 已经认识"翘车头"了，新数据只是让它更准 ——
  这种微调 20~30 个 epoch 就够，不用 100 个。时间直接砍掉 70%。
  2. 冻结主干（freeze=10），只训检测头。反向传播的计算量少一半，而且你数据量不大
  时效果反而更稳。
  3. 图片缓存进内存（cache='ram'）。你有 32GB，1000 张 416px 图才占 500MB
  左右，省掉每轮反复读盘解码，白捡 20~30% 速度。

  另外一个大头：预标注和推理用 OpenVINO 加速。Intel CPU 上把模型导出成 OpenVINO
  格式，推理能快 2~3 倍。预标注 1000 张图从 5 分钟降到 2 分钟。训练还得用
  PyTorch，但推理这块必须上。

  主要改了什么

  新增了一整章「四之二：目标机器是纯 CPU」，这是全文最长也最要紧的一章，里面 6
  条硬性要求：

  1. 必须装 CPU-only 版 PyTorch。默认 pip install torch 会拉 2.5GB 的 CUDA
  版，在你机器上一点用没有，还会把镜像撑到 6GB —— 拷进内网够你受的。装 +cpu
  版镜像能压到 1.5GB。
  2. 线程数设 14（物理核）而不是 28。超线程对 YOLO
  训练往往是负优化。而且这几个环境变量必须在 import torch 
  之前设，我在提示词里特意点了这个坑。
  3. 所有模型调用强制 device='cpu'、amp=False。CPU 没有混合精度，amp=True
  会触发一次多余的 GPU 检查甚至联网下载，离线环境直接卡死。
  4. 预标注走 OpenVINO。模型注册时后台自动导出一份，推理快 2~3 倍。
  5. 图片缓存按数据量自动决定 ram/disk/关闭，别一股脑塞内存把 32G 撑爆。
  6. docker-compose 必须设 shm_size: 2gb，否则 DataLoader 多进程会莫名 bus error
  —— 这是 Docker 里跑 PyTorch 最常见的坑，不设必踩。

  训练默认参数全换了：yolo26n + 416px + 40 epoch + freeze=10 +
  patience=10（原来是 yolo26s + 640 + 100
  epoch，那套配置在你机器上要跑一天多）。

  新增两个必做功能：

  - 耗时预估器 —— 参数一改就实时算，第 1 个 epoch 跑完用实测校准。超 12
  小时红色警告并给出具体降参建议，超 24 小时要勾选确认才能提交。CPU
  训练不给预估，用户三小时后必然以为系统死了。
  - 断点续训 + 容器重启恢复 —— 应用启动时扫描"还在 running 但进程已经没了"的任务
  ，标记为已中断，给个「继续训练」按钮。跨夜训练遇上重启不至于全白跑。同时
  restart: unless-stopped 但不自动重跑训练，避免死循环把机器跑垮。

  部署部分补了 CentOS 特有的两个坑：SELinux 默认 enforcing，volume 挂载不加 :z
  容器读不到 data/；firewalld 要手动放行 5016。

  一个我给你标了红线的建议

  提示词里我把"在已有模型上继续训练"设成了训练页的默认选项，而不是从 COCO
  从头训。

  你手上 0517_yolo26s 已经认识翘车头了，新数据只是让它更准 —— 这种微调 20 
  轮就够，从零训要 40+ 轮。在没有 GPU 的机器上，这一个选择就是"睡一觉起来训好了"
  和 "等两天" 的区别。
