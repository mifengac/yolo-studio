# CPU 训练调优说明（大白话）

目标机器：Intel Xeon E5-2697 v3（14 核 28 线程）、32 GB 内存、**没有显卡**。

## 为什么默认用 yolo26n + 图片尺寸 416？

- **n（微）** 比 **s（小）** 大约快 3 倍，精度略低，但卡口场景目标不小，往往够用。
- 图片边长从 640 降到 416，计算量大约变成原来的 40% 左右（按边长平方算）。
- 一轮训练在这台机器上，1000 张图、yolo26n、640、不冻结，大约 **10 分钟**；用 416 + 冻结主干，能再砍一大截。

## 什么时候该「在已有模型上微调」，什么时候「从零开始」？

| 情况 | 建议 |
|---|---|
| 类别仍是翘车头 / 多人骑车，只是换了卡口、补了数据 | **微调**已有 `0517_*.pt`，15~25 轮通常够 |
| 要加新类别（比如未戴头盔），且类别数量/顺序和旧模型对不上 | **从零开始**用 yolo26n.pt，或单独训一个新模型 |
| 旧模型类别列表和当前数据集完全一致 | 优先微调，省时间约 60% |

微调时系统会检查：底模认识的类别数量和顺序必须和数据集一致，否则会用人话报错。

## 一次训练大概要多久？

界面上有**实时预估**。经验公式基线：

> 1000 张 · yolo26n · 640 · 不冻结 ≈ **10 分钟/轮**

再按图片数、尺寸、n/s、是否冻结、是否内存缓存缩放。  
第一轮跑完后，会用实测速度校准剩余时间。

**超过 12 小时**会红字警告并给降参建议；**超过 24 小时**默认不让提交，除非勾选「我知道会很久」。

## 内存不够怎么办？

系统会按数据量自动选缓存：

- 预估缓存 < 8 GB → 放内存（最快）
- 8~16 GB → 放磁盘缓存
- \> 16 GB → 不缓存

若仍吃紧：减小 `batch`、减小 `imgsz`、少开别的程序。Docker 已设 `shm_size: 2gb`，避免 DataLoader 报错。

## 训练中断了怎么办？

容器重启或断电后，任务会变成「已中断」，点 **继续训练** 会从 `last.pt` 接着跑。  
**不会**在容器自动重启时偷偷重跑训练，避免死循环把机器跑满。

## 预标注为什么比训练快？

预标注优先用 **OpenVINO** 导出模型（注册/发布时自动导出，失败则退回 `.pt`），在 Intel CPU 上通常比纯 PyTorch 快 1.5~3 倍。
