# 切图范围调整 + 预标注去重 + 两端参数同步（实现提示词）

> 自包含任务书。涉及**两个项目**：`~/project/yolo-studio/` 与 `~/project/bczj-classifier/`。
> 所有结论均有实测数据支撑（2026-07-31）。

## 零、背景：为什么要改切图范围

生产环境暴露的核心问题：**模型把行人、汽车司机误判成"未戴头盔"**。

根因分析（实测）：要区分"骑手"和"行人"，模型必须能看到**车**（后视镜、车把、车身）。但当前切图参数 `bottom_ratio=0.55` 只取上半身，车基本被切掉了。

实测数据 —— 在已切好的 120 张图上重新跑 COCO 检测：

```
能检出二轮车部件的:  19 张 (16%)
检不出的:           101 张 (84%)
```

不同切图范围的对比实验（同一批原图，62 个目标）：

| `bottom_ratio` | 切图内容 | 能检出车的比例 |
|---|---|---|
| **0.55（当前）** | 只到腰部 | **6%** |
| 0.75 | 到车把 | 11% |
| 1.0 | 整个人 | 13% |
| **1.3（目标值）** | **人 + 车身** | **32%** |

结论：**必须切到 1.3，模型才有机会看到车**。现在等于"想教模型认出没骑车的人，但教材里根本没拍到车"。

**注意**：标注方式**不变**，仍然只框头部。车不需要标注——它是背景上下文，模型会自动利用（感受野覆盖整张切图）。

## 一、P0 yolo-studio：切图默认范围改为 1.3

### 位置

`app/services/crop_svc.py` 的 `_DEFAULT_PARAMS`（约 31~35 行）。

### 改法

```python
_DEFAULT_PARAMS = {
    "model": "yolo26n.pt",
    "target_class": "person",
    "conf": 0.25,
    "imgsz": 1280,
    "min_box_h": 100,
    "pad_ratio": 0.25,
    "top_ratio": -0.15,
    "bottom_ratio": 1.30,   # ← 从 0.55 改为 1.30：必须包含车身，否则无法区分骑手与行人
    "max_crops": 8000,
    ...
}
```

同时更新前端「智能切图导入」高级参数面板的默认值与说明文字：

```
下边界比例 (bottom_ratio)：1.30
说明：取到 person 框高的 130%，包含车身。
      这是区分"骑手"与"行人"的关键——切得太短看不到车，模型学不会拒绝行人。
```

### 顺带调整

`min_box_h` 保持 100 不变。但因为切图变高了，建议在切图时**记录实际切图尺寸**并在完成消息里给出中位数，方便观察：

```
切图入库 1405 张，中位尺寸 340×430
```

### 验收

1. 用同一批原图分别按 0.55 和 1.30 切图，人眼抽查 10 张，1.30 的切图应能明显看到车把/后视镜/车身
2. 头部在切图中仍清晰可辨（占切图高度约 1/6，缩放到 416 后约 40~50 像素）
3. 现有已切图的数据集不受影响（本次只改默认值，不回溯处理历史数据）

## 二、P0 yolo-studio：预标注重复框去重

### 问题

用户反馈：预标注后**同一个目标被框了好几次**（例如一个戴头盔的人身上叠了 3 个框，位置几乎重合）。

**这会严重破坏训练**：模型会学到"一个头要输出多个框"，导致 precision 暴跌，而且症状隐蔽、难以定位。

### 改法（两条都做）

**① 预标注默认 `iou` 阈值收紧**

`app/schemas.py` 的 `AutolabelRequest`：

```python
iou: float = 0.35   # 从 0.5 收紧到 0.35，重叠超过此比例的预测框会被 NMS 合并
```

前端预标注面板里这个参数要可调，并加说明：
「框重叠合并阈值，越小越不容易出现重复框；发现同一目标被框多次时调低」

**② 新增「清理重复框」功能（兜底）**

即使调了 iou，跨类别的重复框（同一位置同时被判 helmet 和 no_helmet）仍可能出现。加一个数据集级操作：

```
POST /api/datasets/{id}/annotations/dedup
body: { iou_threshold: 0.6, scope: "auto" | "all" }
```

逻辑：

- 按图片分组，对每张图的框做 **NMS**（跨类别）
- 两个框 IoU 超过阈值时，**保留置信度高的那个**，删除其余
- `scope="auto"` 只处理 `source='auto'` 的框（默认，安全）；`"all"` 包括人工标注的
- 返回统计：`{"deleted": 312, "affected_images": 145}`
- 前端在数据集页加入口，二次确认时提示"将删除 N 个重复框，保留每组中置信度最高的"

**默认只清理 `auto` 的框**——人工标注的可能有意图（比如两个人挨得很近），不要擅自删。

### 验收

1. 造一个数据集，人为让预标注产生重复框（把 iou 调到 0.9），确认能复现
2. 跑「清理重复框」，同位置多框应只剩置信度最高的一个
3. 人工标注的框在 `scope="auto"` 下**一个都不能少**
4. 预标注默认 iou 改为 0.35 后，重复框明显减少

## 三、P0 bczj-classifier：切图参数必须同步

### 这是最容易漏、后果最严重的一步

**训练时怎么切图，推理时就必须怎么切图。** 如果 yolo-studio 用 1.3 训练，而 bczj-classifier 仍用 0.55 推理，模型看到的画面构图完全不同，**准确率会断崖式下跌**，而且从代码上完全看不出问题。

### 位置

`~/project/bczj-classifier/app/config.py` 的 `CROP_PARAMS`。

### 改法

```python
CROP_PARAMS = {
    "det_conf": 0.25,
    "det_imgsz": 1280,
    "helmet_imgsz": 416,
    "min_box_h": 100,
    "pad_ratio": 0.25,
    "top_ratio": -0.15,
    "bottom_ratio": 1.30,   # ← 必须与 yolo-studio 训练时的切图参数完全一致
}
```

并在这段配置上方加注释，写明这个约束：

```python
# ★ 本参数必须与 yolo-studio 训练模型时使用的切图参数保持一致。
# 训练用 1.3 而推理用 0.55（或反之），模型准确率会大幅下降且难以排查。
# 修改前请确认对应模型是用哪套参数训练的。
```

### 建议：把切图参数写进模型元数据

更彻底的做法是让参数跟着模型走，而不是靠人记：

- yolo-studio 发布模型时，把切图参数写进 `model` 表（或与 `.pt` 同名的 `.json` 旁文件）
- bczj-classifier 加载模型时读取并使用，读不到才用默认值
- 这样换模型时参数自动跟着变，不会再出现两边不一致

本轮可以先做硬编码同步，元数据方案作为后续优化。

### 验收

1. 两个项目的 `bottom_ratio` 都是 1.30
2. 用同一张原图，在两边分别切图，**切出的图应当像素级一致**（可用 hash 对比）
3. 新模型上线后跑 20 张真实图，人眼核对准确率不低于线下验证水平
