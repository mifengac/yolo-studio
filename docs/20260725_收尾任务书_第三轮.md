## 二、三个遗留小口子

都是第二轮审查发现的，改动都很小。

### 2.1 `dedup` 没进重任务池（影响最实际）

- **位置**：`app/config.py:71` 的 `HEAVY_TASK_TYPES`
- **问题**：集合里有九个类型，唯独漏了 `dedup`。而第二轮 P1-G 刚把去重从 aHash 升级成 pHash + DCT，**计算量明显变大**。现在它走 light 池（4 个 worker），意味着训练进行时 dedup 会跟训练抢那 14 个核，甚至可能同时跑多个。
- **改法**：集合里加 `"dedup"`。
- **验收**：训练进行中发起去重 → 去重任务显示"等待其他重任务结束…"，不与训练并发。

### 2.2 `__import__("threading")` 丑陋写法

- **位置**：`app/tasks.py:22`
  ```python
  _heavy_inflight_lock = __import__("threading").Lock()
  ```
- **成因**：第二轮拆池时把文件头的 `import threading` 删了，后面又需要，就用 `__import__` 绕过去。功能没问题，但可读性差。
- **改法**：文件头恢复 `import threading`，这里改回 `threading.Lock()`。

### 2.3 heavy 计数可能泄漏

- **位置**：`app/tasks.py` 的 `submit_task`
- **问题**：`_heavy_inflight += 1` 之后才调 `_heavy_executor.submit(...)`。若 submit 抛异常（例如池已 shutdown 时投递，抛 `RuntimeError`），计数不会回滚，此后**所有重任务都会一直显示"等待其他重任务结束…"**。不影响实际执行，但界面文案会一直骗人。
- **改法**：
  ```python
  with _heavy_inflight_lock:
      _heavy_inflight += 1
  try:
      _heavy_executor.submit(_run_task, task_id, True)
  except Exception:
      with _heavy_inflight_lock:
          _heavy_inflight = max(0, _heavy_inflight - 1)
      raise
  ```
- 顺带确认 `stop_workers()` 里 `cancel_futures=True` 取消掉的任务不会留下计数残留（进程随后退出的话影响有限，但若只重启 workers 不重启进程就会残留）。

### 2.4 镜像里 opencv 装了两份（体积优化，可选）

- **位置**：`Dockerfile` 的 pip install 步骤
- **问题**：`requirements.txt` 钉的是 `opencv-python-headless`，但 ultralytics 硬依赖完整版 `opencv-python`，结果两个都装进镜像：`opencv_python.libs` 116 MB + `opencv_python_headless.libs` 81 MB，**白占约 116 MB**。
- **改法**：pip install 之后加一句
  ```dockerfile
  && pip uninstall -y opencv-python
  ```
  两个包提供的是同一个 `cv2` 模块，保留 headless 即可（Dockerfile 已装 `libgl1`，就算判断失误也不会崩）。
- **改完必须重新验证**：`docker build` → 容器内 `python -c "import cv2;print(cv2.__version__)"` 正常 → 跑通 `smoke_test.py`。**如果卸载后 ultralytics 或 cv2 报错，就还原这条改动**，116 MB 不值得冒险。

### 关于镜像体积标准

实测当前镜像 **2.94 GB**，超过此前定的 "< 2 GB"。体积构成：torch 750 MB + polars 206 MB（ultralytics 8.4 的新依赖）+ openvino 177 MB + opencv 双份 197 MB。

**"< 2 GB" 这个标准是基于旧版 torch 2.5.1 估算的，已不符合实际，不是实现问题。** 请把 `README.md` 和验收标准里的镜像体积预期改为 **< 3 GB**，并在 README 里注明实测值，免得以后有人误判成缺陷。
