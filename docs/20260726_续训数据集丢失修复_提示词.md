# yolo-studio 续训丢失数据集参数修复（实现提示词）

> 自包含任务书。项目位于 `~/project/yolo-studio/`。
> **本次是一起已经造成实际损失的事故**：用户 40 轮训练的成果（27 轮进度）被续训功能静默销毁。
> 根因已完整定位并有证据链（2026-07-26）。

## 零、事故经过

用户的训练跑到第 27 轮时电脑睡眠中断，状态修正为 `interrupted` 后点了「继续训练」。结果：

- 界面显示"训练成功，40/40 轮"
- 实际上模型被**在 ultralytics 内置的 `coco8` 样例数据集上重训了 40 轮**
- 40 轮只用了 **23.7 秒**（原本 27 轮用了 38 分钟）
- 模型类别头从 `[helmet, no_helmet]` **变回 COCO 80 类**
- `best.pt` 和 `last.pt` **全部被覆盖**，27 轮的成果彻底丢失

### 证据链

首次训练命令（正确）：

```

  ... freeze=10 data=/…/exports/train_20260726_080734_b50387/data.yaml
```

续训命令（`train_svc.py` 生成，**缺 data**）：

```
yolo detect train model=/…/weights/last.pt epochs=40 imgsz=416 batch=16 \
  ... resume=True
                    ↑ 没有 data=，也丢了 freeze
```

训练产物 `args.yaml` 的实锤：

```yaml

epochs: 40
resume: false             # ← 连 resume 都没真正生效
```

`last.pt` 内记录的训练参数：

日志里 `val: Caching images 4/4` —— coco8 的验证集正好 4 张图。

上一轮验收时确实测过续训，看到"跑满 20 轮、状态 success"就判定通过了。但当时的测试数据集是 12 张随便标的假框，mAP 本来就接近 0，**完全掩盖了"其实在训 coco8"这个事实**。

## 一、P0 ★ 续训必须显式传全部训练参数

### 位置

`app/services/train_svc.py`，续训命令构造处（搜索 `resume=True` 或 `_handler_resume`）。

### 根因

依赖 `resume=True` 让 ultralytics 自己从 `last.pt` 恢复参数。但这个机制在当前版本（ultralytics 8.4.105）**不可靠**：参数恢复失败时它不报错，而是**静默退回 `coco8.yaml` 默认值**，并且把 `resume` 重置为 `false`。

### 改法

续训命令必须把**首次训练的全部关键参数原样重新传一遍**，一个都不能少：

```python
def _build_resume_cmd(job: dict, last_pt: Path) -> list[str]:
    """续训命令：显式重传所有参数。
    绝不能只靠 resume=True —— ultralytics 恢复失败会静默退回 coco8.yaml。
    """
    p = json.loads(job["params"] or "{}")
    data_yaml = p.get("data_yaml") or _find_export_yaml(job)   # 见下方说明
    if not data_yaml or not Path(data_yaml).is_file():
        raise FileNotFoundError(
            f"找不到本次训练的 data.yaml（{data_yaml}），无法安全续训。"
            "请重新发起一次完整训练。"
        )
    return [
        _resolve_yolo_bin(), "detect", "train",
        f"model={last_pt}",
        f"data={data_yaml}",                    # ★ 事故根因，必须显式传
        f"epochs={p['epochs']}",
        f"imgsz={p['imgsz']}",
        f"batch={p['batch']}",
        f"workers={p.get('workers', 8)}",
        f"freeze={p.get('freeze', 10)}",        # ★ 之前也丢了
        f"patience={p.get('patience', 10)}",
        f"cache={p.get('cache', 'ram')}",
        "device=cpu", "amp=False",
        f"project={config.RUNS_DIR}", f"name={job['id']}", "exist_ok=True",
        "verbose=True", "resume=True",
    ]
```

**关于 `data_yaml` 的来源**：首次训练时把导出的 yaml 绝对路径写进 `train_job.params`（如果还没存的话，本次一并加上）。兜底再用约定路径去找：
`data/datasets/<dataset_id>/exports/<job_id>/data.yaml`。

**找不到就拒绝续训并给人话提示**，绝不能带着残缺参数硬跑——这正是本次事故的成因。

### 附带修复：`resume_job` 的状态校验

现在 `resume_job`（`train_svc.py:569` 附近）允许 `interrupted/failed/canceled` 续训。保持不变，但要在**启动前**校验 `data_yaml` 存在，不存在就直接报错，不要等到进程跑起来才发现。

## 二、P0 ★ 加熔断：训练启动后校验实际使用的数据集

只保证"传参正确"还不够。ultralytics 这类"参数无效就静默用默认值"的行为，必须有**独立的事后校验**兜住。

### 改法

训练/续训进程启动后（首个 epoch 完成前后），读取 `run_dir/args.yaml`，核对关键字段：

```python
def _verify_train_args(run_dir: Path, expect_data: str, expect_imgsz: int) -> Optional[str]:
    """返回 None 表示正常，否则返回错误描述。"""
    f = run_dir / "args.yaml"
    if not f.is_file():
        return None                      # 还没生成，下次轮询再查
    try:
        import yaml
        args = yaml.safe_load(f.read_text(encoding="utf-8")) or {}
    except Exception:
        return None
    actual = str(args.get("data") or "")
    if actual and Path(actual).resolve() != Path(expect_data).resolve():
        return (f"训练实际使用的数据集是 {actual}，与预期的 {expect_data} 不符"
                f"（ultralytics 可能静默退回了默认数据集）")
    if args.get("imgsz") and int(args["imgsz"]) != int(expect_imgsz):
        return f"训练实际 imgsz={args['imgsz']}，与预期 {expect_imgsz} 不符"
    return None
```

在轮询循环里调用一次（只需查一次，`args.yaml` 训练开始就写好且不再变）：

```python
err = _verify_train_args(run_dir, data_yaml, imgsz)
if err:
    _kill_pid(proc.pid)
    update_job(job_id, status="failed", finished_at=db.utcnow(), pid=None)
    append_log(log_path, f"训练参数校验失败，已终止：{err}")
    raise RuntimeError(err)
```

**必须立即终止**，而不是让它跑完再报告——本次事故里如果有这道校验，模型就不会被覆盖。

## 三、P1 续训前备份权重

即使有了上面两道防线，续训本质上仍是**覆盖式写入** `best.pt` / `last.pt`。一旦出意外，已有成果不可恢复。

### 改法

`resume_job` 启动前，把当前权重备份一份：

```
run_dir/weights/best.pt  →  run_dir/weights/backup_before_resume_<时间戳>/best.pt
run_dir/weights/last.pt  →  同上
```

- 备份失败不阻断续训，但要记警告日志
- 续训**成功完成**后可以删除备份（或保留，权重才 5 MB，留着更保险）
- 在任务详情接口里暴露备份路径，让用户知道有退路

一个模型 5 MB，这个保险太便宜了，值得做。

## 四、验收标准（必须真跑，不能只看代码）

### 关键：验证续训不能只看状态和轮数

上一轮就是因为只看了"success + 20 轮"就放行，才让这个 bug 跑到用户的真实模型上。

| 项 | 验证方法 |
|---|---|
| **续训用对数据集** | 续训完成后，`cat run_dir/args.yaml \| grep data:` **必须**指向本 job 的 `exports/<job_id>/data.yaml`，**绝不能是 `coco8.yaml`** |
| **类别没变** | `python -c "from ultralytics import YOLO; print(YOLO('best.pt').names)"` 必须还是数据集的类别（如 `{0:'helmet',1:'no_helmet'}`），不能变成 COCO 80 类 |
| **训练时长合理** | 续训 N 轮的耗时应与首次训练每轮耗时相当。**几十秒跑完几十轮 = 数据集错了** |
| **熔断生效** | 人为把 `data_yaml` 路径改成一个不存在的文件 → 续训应**拒绝启动**并给人话提示；或人为让 ultralytics 退回默认数据集 → 应被熔断终止 |
| **备份存在** | 续训启动后，`weights/backup_before_resume_*/` 里有原 `best.pt` |
| 轮次接续 | `results.csv` 的行数从断点继续增长，不是从 1 重新计数 |
| 回归 | 首次训练（非续训）一切正常；训练完整跑完后 `metrics_from` 仍是 `best.pt val` |

### 建议的验证流程

```bash
# 1. 起一个 20 轮训练（用真实数据集，不要用假数据）
# 2. 跑到第 5 轮左右 kill <pid>（SIGTERM）
# 3. 确认状态 interrupted、轮数真实
# 4. 点续训
# 5. ★ 立刻检查 args.yaml：
cat data/runs/<job_id>/args.yaml | grep -E "^data:|^imgsz:|^freeze:"
# 6. 跑完后检查类别和耗时
```
