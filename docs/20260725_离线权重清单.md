# 离线权重清单

在**有网机器**上下载后，全部放到 `yolo-studio/weights/`，再随 Docker 镜像或 U 盘带进内网。

## 一、一键下载（推荐，命令可直接复制执行）

下面的 URL 与体积均已在 2026-07-25 实测验证（HTTP 200，体积为实际下载值）。

```bash
cd ~/project/yolo-studio
mkdir -p weights

BASE="https://github.com/ultralytics/assets/releases/download/v8.4.0"

# 1) 从零训练默认底模（CPU 首选）
curl -fL -o weights/yolo26n.pt        "$BASE/yolo26n.pt"

# 2) 从零训练备选（CPU 上比 n 慢约 3 倍，非必要不用）
curl -fL -o weights/yolo26s.pt        "$BASE/yolo26s.pt"

# 3) 开放词表零样本预标注（输入英文描述直接出框，新类别冷启动用）
curl -fL -o weights/yolov8s-worldv2.pt "$BASE/yolov8s-worldv2.pt"

# 4) SAM 点选辅助（点一下自动出框；只能用 MobileSAM，见下方说明）
curl -fL -o weights/mobile_sam.pt     "$BASE/mobile_sam.pt"

# 5) 已训好的业务模型（冷启动预标注 + 微调底模），从本机既有项目拷贝
cp ../bczj-classifier/models/0517_yolo26n_wheelie_multi-rider.pt weights/
cp ../bczj-classifier/models/0517_yolo26s_wheelie_multi-rider.pt weights/

# 6) 开放词表额外需要 CLIP 文本塔权重（约 338MB，放 weights/clip/ 供 Docker 拷进镜像）
mkdir -p weights/clip ~/.cache/clip
# 本机若已有：
cp -n ../bczj-classifier/weights/clip/ViT-B-32.pt weights/clip/ 2>/dev/null || true
# 或首次使用开放词表时 ultralytics 会自动下到 ~/.cache/clip/，再拷贝：
# cp ~/.cache/clip/ViT-B-32.pt weights/clip/
cp -n weights/clip/ViT-B-32.pt ~/.cache/clip/ 2>/dev/null || true

ls -lh weights/ weights/clip/ 2>/dev/null
```

**下载后校验**（确认文件完整、能被 ultralytics 加载）：

```bash
.venv/bin/python - <<'PY'
from pathlib import Path
from ultralytics import YOLO
for f in ["yolo26n.pt", "yolo26s.pt", "yolov8s-worldv2.pt",
          "0517_yolo26n_wheelie_multi-rider.pt", "0517_yolo26s_wheelie_multi-rider.pt"]:
    p = Path("weights") / f
    if not p.is_file():
        print(f"缺失: {f}"); continue
    try:
        m = YOLO(str(p))
        print(f"OK  {f}  类别数={len(m.names)}  {p.stat().st_size/1048576:.1f} MB")
    except Exception as e:
        print(f"损坏 {f}: {e}")
# mobile_sam 走 SAM 接口，单独验证
try:
    from ultralytics.models.sam import Predictor as SAMPredictor
    print("OK  mobile_sam.pt 可用（由 sam_svc 在首次点选时加载）")
except Exception as e:
    print("SAM 接口不可用:", e)
PY
```

## 二、清单明细

| 文件名 | 用途 | 实测体积 | 获取方式 |
|---|---|---|---|
| `yolo26n.pt` | 从零训练默认底模（CPU 首选） | **5.3 MB** | `$BASE/yolo26n.pt` |
| `yolo26s.pt` | 从零训练备选（CPU 慢约 3 倍） | **19.5 MB** | `$BASE/yolo26s.pt` |
| `yolov8s-worldv2.pt` | 开放词表零样本预标注 | **24.7 MB** | `$BASE/yolov8s-worldv2.pt` |
| `mobile_sam.pt` | SAM 点选辅助（**禁止用原版 SAM**） | **38.8 MB** | `$BASE/mobile_sam.pt` |
| `0517_yolo26n_wheelie_multi-rider.pt` | 冷启动预标注 + 微调底模（微） | 5.4 MB | 从 `~/project/bczj-classifier/models/` 拷贝 |
| `0517_yolo26s_wheelie_multi-rider.pt` | 冷启动预标注 + 微调底模（小） | 20 MB | 从 `~/project/bczj-classifier/models/` 拷贝 |
| `clip/ViT-B-32.pt` | YOLO-World 文本编码（开放词表必用） | **338 MB** | 构建机放 `weights/clip/ViT-B-32.pt`；**Docker 多阶段整理后只进 `/root/.cache/clip/` 一份**（不会再出现在镜像 `/app/weights/clip/`）。本地开发再 `cp` 到 `~/.cache/clip/` |

其中 `$BASE` = `https://github.com/ultralytics/assets/releases/download/v8.4.0`

检测/SAM 权重合计约 **114 MB**；加上 CLIP 约 **452 MB**。

**Python 依赖**：开放词表还需要 `clip` 包（`pip install git+https://github.com/ultralytics/CLIP.git`），`run.sh` / `Dockerfile` 已处理。

> **关于 release tag**：`v8.4.0` 是本机安装的 ultralytics 8.4.105 默认使用的资产版本（源自 `ultralytics/utils/downloads.py` 的 `attempt_download_asset(release="v8.4.0")`）。
> 如果以后升级 ultralytics 导致该 tag 下载不到某个文件，用下面这句查当前版本对应的 tag，不要凭印象改：
> ```bash
> .venv/bin/python -c "import inspect;from ultralytics.utils import downloads;print([l for l in inspect.getsource(downloads.attempt_download_asset).splitlines() if 'release' in l][0])"
> ```

## 三、mobile_sam.pt 是干什么的

**SAM**（Segment Anything Model）是"分割一切"模型：在图上**点一下**，它自动把你点中的物体轮廓抠出来。

在本项目里的具体用途：标注时不用手动拖拽画框，鼠标往目标（比如翘车头的摩托车）上一点，紧贴目标的框就自动生成了，比手拉框快约 3 倍。对应标注页的 `E` 键点选模式。

**为什么必须用 MobileSAM，不能用原版 SAM**：

| | 编码器 | 体积 | CPU 单张耗时 |
|---|---|---|---|
| 原版 SAM (`sam_l.pt` / `sam_b.pt`) | ViT-H / ViT-L | 1.2~2.4 GB | 10 秒以上 ❌ |
| **MobileSAM** | TinyViT | **38.8 MB** | 1.5~3 秒 ✅ |

在这台无 GPU 的 E5-2697 v3 上，原版 SAM 点一下要等十几秒，完全没法用来标注；MobileSAM 把编码器换成轻量 TinyViT，体积小 30 倍、速度快几十倍，精度接近。所以设计文档里硬性规定**只用 MobileSAM**。

**实际体验**：同一张图第一次点选 1.5~3 秒（做图像编码），之后再点同一张图就很快（< 200 ms）——因为编码结果被缓存了（见 `app/services/sam_svc.py` 的 embedding 缓存）。切换到下一张图时会后台预热。

## 四、字体（离线训练画图用）

| 文件 | 用途 | 说明 |
|---|---|---|
| `Arial.ttf` | ultralytics 画图/标注框文字 | **Docker 构建已自动处理**：把系统 `DejaVuSans.ttf` 复制为 `/root/.config/Ultralytics/Arial.ttf`（见 `Dockerfile`）。注意这不是真的 Arial，是 DejaVu 改名顶替——ultralytics 只按路径加载，不校验字体本身，能正常工作。内网**无需**单独下载。<br>本地开发若报字体缺失，手工放一个到 `~/.config/Ultralytics/Arial.ttf` 即可。 |

## 五、注意事项

1. **代码里只用绝对路径加载模型**，不会出现 `YOLO('yolov8n.pt')` 这种触发联网下载的写法——这是离线可用的前提，改代码时务必保持。
2. `weights/` 默认不进 git（见 `.gitignore`），只跟踪 `.gitkeep`。
3. 训练产物会复制到 `data/models/`，发布后**后台异步**导出 OpenVINO 目录 `data/models/<id>_openvino_model/`，状态见 `model.ov_status`（pending → exporting → ready/failed）；导出失败自动降级用 `.pt`，不影响使用。
4. 权重齐备后，以下三条功能才可用，缺一不可：
   - `yolo26n.pt` / `yolo26s.pt` → **从零训练**（不备只能在 0517 模型上微调）
   - `yolov8s-worldv2.pt` → **开放词表零样本标注**
   - `mobile_sam.pt` → **SAM 点选辅助**
5. Docker 构建前必须备齐：`weights/*.pt`（检测/SAM）+ `weights/clip/ViT-B-32.pt`。最终镜像里 CLIP 只在 `/root/.cache/clip/ViT-B-32.pt`，`/app/weights/` 仅检测/SAM 权重。
