# yolo-studio 新增「智能切图导入」功能（实现提示词）

> 自包含任务书。项目位于 `~/project/yolo-studio/`，当前 HEAD 为第四轮修复后状态。
> 本文所有参数均经实测标定（2026-07-25），不是拍脑袋定的。

## 一、为什么需要这个功能

用户的新场景是**头盔识别**（戴 / 不戴），数据源是卡口抓拍原图。

实测数据（405 张真实样本）：

- 原图尺寸 **4096×2256**（800 万像素全景路口图），一张图里有 2~5 辆二轮车
- 骑手**头部在原图里只有 50~100 像素**，占画面宽度 1.5%~4%
- 训练 `imgsz=416` 时，原图缩小到 1/9.8，**头部只剩 6 像素** —— YOLO 能稳定检出的下限约 16~20 像素，**根本无法判断有没有戴头盔**

这与此前的「翘车头」任务有本质区别：翘车头判的是**整车姿态**（大目标），头盔判的是**头部特征**（极小目标）。同一套流程直接套用必然失败。

**解决办法**：训练前先把每个骑手从大图里切出来，在切图上标注和训练。

实测验证（用 `weights/yolo26n.pt`，COCO 预训练，本身就含 `person` 类）：

```
0000001_getData.jpg (4096x2256, 夜间)  imgsz=1280
  person conf=0.89  框 201x347 px
  person conf=0.78  框 185x316 px
  person conf=0.72  框 197x328 px

切图结果：person 框 224x378 → 上半身切图 337x265，头部占切图约 1/3，
         夜间背影也能一眼看出没戴头盔
```

**结论**：不需要专门的二轮车检测模型，COCO 预训练的 `person` 类足够可靠。

## 二、要做的功能

数据集页新增入口「智能切图导入」：用检测模型把大图里的人切出来，切图作为新数据集的图片入库。原始大图**不入库**。

### 2.1 两个入口

```
POST /api/datasets/{dataset_id}/crop-import/zip     上传大图 ZIP → 切图入库到该数据集
POST /api/datasets/{dataset_id}/crop-import/from/{src_dataset_id}
                                                    从已有数据集（大图）切图到本数据集
POST /api/datasets/{dataset_id}/crop-import/preview  先切 N 张预览，不入库
GET  /api/tasks/{task_id}                            复用现有任务查询
```

### 2.2 参数（默认值已实测标定，不要随意改）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `model` | `weights/yolo26n.pt` | 切图用的检测模型（COCO 预训练） |
| `target_class` | `person` | 目标类别名；也允许传 `motorcycle` 等其它 COCO 类 |
| `conf` | `0.25` | 检测置信度 |
| `imgsz` | **`1280`** | ★ **必须 1280**。用 416 检测大图会漏掉绝大部分小目标，实测 1280 才能稳定检出 |
| `min_box_h` | `100` | 框高小于此值的丢弃（太小的目标切出来也看不清头盔） |
| `pad_ratio` | `0.25` | 左右各外扩框宽的 25%（**头盔边缘常超出 person 框，必须外扩**） |
| `top_ratio` | `-0.15` | 上边界：从框顶再往上扩 15% 框高 |
| `bottom_ratio` | `0.55` | 下边界：取到框高的 55%（**上半身即可，头盔在头部，切全身会让头部占比变小**） |
| `max_crops` | `8000` | 单次任务切图数量上限 |

切图区域计算（照此实现，已实测有效）：

```python
x1, y1, x2, y2 = box            # person 框
bw, bh = x2 - x1, y2 - y1
pad = bw * pad_ratio
cx1 = max(0, x1 - pad)
cx2 = min(W, x2 + pad)
cy1 = max(0, y1 + bh * top_ratio)      # top_ratio 为负 = 向上扩
cy2 = min(H, y1 + bh * bottom_ratio)
crop = img.crop((cx1, cy1, cx2, cy2))
```

### 2.3 ★ 最关键的一点：group_key 必须设为原图文件名

同一张路口大图切出来的 3 个骑手，**背景、光照、路面完全相同**。如果其中一个进训练集、另一个进验证集，模型靠背景就能"记住"答案，**mAP 会虚高得离谱，一上线就露馅**。

`app/services/export_svc.py` 的数据集划分已经是按 `group_key` 分组的，只要切图入库时把它填对，这个坑自动避开：

```python
dataset_svc.import_files(
    dataset_id,
    [(crop_filename, crop_bytes)],
    source="crop",
    group_key=src_image_filename,   # ★ 原始大图的文件名
)
```

`import_files` 的签名见 `app/services/dataset_svc.py:287`，`group_key` 参数现成，不用改。

### 2.4 切图文件命名（保证可追溯）

```
{原图名去扩展名}_p{序号:02d}.jpg
例：0000007_imgu.jpg → 0000007_imgu_p01.jpg / _p02.jpg / _p03.jpg
```

这样出了问题能一眼看出切图来自哪张原图、是第几个目标。

### 2.5 预览模式（必做）

参数是否合适必须先看效果，不能切完 5000 张才发现外扩太少把头盔切掉了。

`POST .../crop-import/preview`：只处理前 N 张（默认 20）大图，**返回切图的 base64 缩略图列表**，不入库、不落盘（或落到临时目录定时清理）。前端以网格展示，用户确认后再点「开始全量切图」。

## 三、实现要点

### 3.1 走后台任务

切图是 CPU 密集操作：**CPU 上 `imgsz=1280` 检测一张 4096×2256 的大图约 0.5~1 秒**，2000 张要 20~30 分钟。必须走现有任务框架：

1. 在 `app/config.py` 的 `HEAVY_TASK_TYPES` 里加 `"crop_import"`（该集合当前有 10 个类型，见 `config.py:71`）
2. `app/main.py` 里 `tasks.register_handler("crop_import", crop_svc.run_crop_import)`
3. 新建 `app/services/crop_svc.py`
4. 进度按"已处理大图数 / 总大图数"更新，message 里带上"已切出 N 张"

### 3.2 内存与磁盘

- ZIP 解压到**临时目录**，逐张读取处理，**不要把所有图片读进内存**（4096×2256 的图一张解码后约 27 MB，2000 张会直接 OOM）
- **边切边入库**，每处理完一张大图就调一次 `import_files` 写盘，不要攒到最后
- 任务结束（含失败/取消）后清理临时目录
- 原始大图**不入库**，处理完即删临时文件

### 3.3 模型加载

复用 `app/infer/engine.py` 的模型缓存加载（带锁、避免重复加载）。注意：

- 推理必须显式 `device="cpu"`
- 切图用的 `yolo26n.pt` 是 COCO 80 类模型，**与数据集自己的类别无关**，不要拿数据集的 `classes` 去校验它
- `target_class` 用**类别名**匹配 `model.names`，不要写死 COCO 索引（不同模型索引不同）

### 3.4 结果统计

任务完成后 message 要给出人话总结：

```
处理大图 2000 张，检出目标 5231 个，
跳过过小目标 892 个，切图入库 4339 张，
其中 12 张大图未检出任何目标
```

「未检出任何目标」的大图要**记进任务 params 的结果里**（列出文件名），用户需要知道哪些图白下载了。

## 四、前端

数据集页的操作按钮区（`web/index.html` 里已有「导入图片」「导入视频」「模型预标注」等按钮）新增「智能切图导入」。

点击后弹出面板：

1. 选择来源：上传 ZIP / 从已有数据集

## 五、验收标准

| 项 | 标准 |
|---|---|
| 预览 | 上传含 5 张大图的 ZIP，预览能返回切图网格，**头部在切图中清晰可辨** |
| 切图质量 | 抽查 20 张切图，头部完整（**没有被上边界切掉**），头部占切图高度约 1/4~1/3 |
| ★ group_key | 数据库里同一张原图切出的多张切图，`group_key` 值**相同且等于原图文件名** |
| ★ 划分隔离 | 切图数据集执行训练导出后，检查 `train`/`val` 两个目录，**同一个 group_key 的切图不能同时出现在两边** |
| 小目标过滤 | `min_box_h=100` 时，明显过小的远处骑手不会被切出来 |
| 进度 | 处理 100 张大图，进度条平滑推进，不卡死 |
| 内存 | 处理 500 张 4096×2256 大图，进程内存**不持续增长**（不能把图都攒着） |
| 取消 | 中途取消能立即停止，已切入库的图保留 |
| 命名 | 切图文件名形如 `原图名_p01.jpg`，可追溯 |
| 回归 | 现有导入图片/视频/预标注/训练功能全部不受影响 |

## 七、上下文：这个功能在整条链路里的位置（供理解，不必实现）

```
【数据准备】
  bczj-classifier 按时间/地区下载卡口大图 → ZIP
      ↓
  yolo-studio 智能切图导入  ← 本次要做的
      ↓
【标注训练】
  在切图上标 helmet / no_helmet → 训练 → 设为默认预标注 → 迭代
      ↓
【生产推理】（另一个项目的改造，本次不做）
  bczj-classifier 改成两级：先 yolo26n 切 person，再用头盔模型判断每个切图
```

**特别注意**：因为训练用的是切图，所以**生产推理也必须先切图**，两边输入分布必须一致。如果训练用切图、推理直接喂全景大图，模型准确率会掉到接近于零。这一点会在 bczj-classifier 的改造任务书里再次强调，此处仅供理解设计意图。
